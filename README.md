## 📌 مشکل

وقتی داخل یک جملهٔ فارسی/عربی یک کلمه یا شناسهٔ انگلیسی قرار می‌گیرد — مثل `SINA`، یک نام فایل، یک مسیر یا نام پکیج — رابط اوپن‌کد بدون الگوریتم بیدی **UAX #9** ترتیب کلمات را به هم می‌ریزد:

```
نوشته‌ی شما (ترتیب منطقی):       سلام من SINA هستم
رندر ناقص (بدون حل):             هستم SINA سلام من
رندر درست (خروجیِ صفحه):         هستم SINA من سلام     ← از راست به چپ = «سلام من SINA هستم»
```

این مشکل هم در **ترمینال/TUI**، هم در **اپ دسکتاپ** و هم در **رابط وب** اوپن‌کد وجود دارد و هنگام تایپ پرامپت (کادر ورودی) و نمایش پیام‌ها و پاسخ‌های مدل دیده می‌شود.

## 🧠 راه‌حل — دو لایه

این پروژه مشکل را در **دو لایه‌ی مکمل** حل می‌کند:

| لایه | ابزار | چه چیزی را درست می‌کند |
| --- | --- | --- |
| **۱) لایهٔ متن (سرویس اوپن‌کد)** | پلاگین `server` (v1) یا `./v2` (v2) | پیام‌های ارسال‌شدهٔ کاربر، پیام‌های تاریخی، پاسخ مدل و خروجی ابزارها — با «ایزوله‌های بیدی» (RLI / LRI / PDI) مطابق UAX #9. از اوپن‌کد **1.18.31** به بعد، رندر ترمینال/دسکتاپ هم جهت را به صورت بومی (`dir="auto"` + plaintext) تشخیص می‌دهد؛ پس این لایه روی ترمینال/وب و نگه‌داشتن توکن‌های LTR تمرکز دارد. نسخهٔ v2 (اوپن‌کد ۲) همان منطق را با API جدید (`ctx.session.hook("prompt"/"context"/...)`) اجرا می‌کند |
| **۲) لایهٔ رابط (دسکتاپ)** | پچ `app.asar` (موتور `patch/lib/patch-asar.mjs` + بسته‌بند هر سیستم‌عامل)، که پلاگین سرور هم خودکار اعمال و ترمیمش می‌کند | **همهٔ سطح‌های متنی رابط**: کادر تایپ زندهٔ پرامپت، پیام‌های چت، عنوان تب/جلسه‌ها و تب‌های ترمینال، منوها، دیالوگ‌ها، توست‌ها، تنظیمات، درخت فایل، نام فایل‌های review، ضمیمه‌ها، پرمیشن‌ها و سؤال‌ها — با تزریق `dir="auto"` + `unicode-bidi: plaintext` به `app.asar` (کد، دیف و خروجی شل عمداً LTR می‌مانند) — به‌همراه فونت **وزیرمتن (Vazirmatn)** برای کل متن رابط |

<details>
<summary>🔍 چطور کار می‌کند؟</summary>

- **پلاگین** به هوک‌های سمت سرور اوپن‌کد وصل می‌شود (`chat.message`، `experimental.text.complete`، `tool.execute.after` و…). برای هر پاراگراف، «اولین کاراکتر قوی» جهت را تعیین می‌کند؛ پاراگراف فارسی/عربی را در `RLI…PDI` می‌گذارد و کلمه‌های انگلیسی/کدِ داخلش (مثل `SINA`، `/path/to/file`) را با `LRI…PDI` «منزوی» می‌کند تا ترتیب‌شان قاطی نشود. این کاراکترهای کنترلِ یونیکد در بافر ترمینال و بافتِ مدل می‌توانند اثر نامطلوب بگذارند (مثل نویز `^` هنگام رندر سلول‌به‌سلول)، پس این تزریق **اختیاری** است (گزینهٔ `inlineControls: true`). در پیش‌فرض، پلاگین هیچ کاراکتر کنترلی تزریق نمی‌کند و حتی کاراکترهای جهت‌دارِ چسبیده به متن (مثل LRM/RLM از کپی‌کردن وب) را حذف می‌کند.
- **پچ دسکتاپ** یک `<style>` و `<script>` به `out/renderer/index.html` داخل `app.asar` اضافه می‌کند. چون از **1.18.31** به بعد خودِ اوپن‌کد پیام‌ها و پاسخ‌ها را بومی درست می‌کند، پچ فقط جاهایی را می‌گیرد که اپ هنوز ندارد: کادر تایپ زنده (`[data-component="prompt-input"]` و `[data-component="prompt-input-v2"]`) و عنوان تب‌ها (`[data-slot="tab-title"]`، `[data-slot="terminal-tab-title"]`) — با اعمال `dir="auto"` + plaintext روی آن‌ها. همین پچ یک `@font-face` از فونت **وزیرمتن** را هم به‌صورت base64 داخل همان صفحه جاسازی می‌کند و با `--font-family-sans` کل رابط را وزیرمتن می‌کند (بدون نیاز به نصب فونت روی سیستم یا اینترنت).
- **هیچ هوکی به رندرر دسکتاپ نمی‌رسد:** پلاگین سرور فقط هوک‌های سرور را دارد، پلاگین CLI فقط ترمینال است، و سیستمِ «GUI extensions» اوپن‌کد در نسخهٔ منتشرشده فقط برای buildهای توسعه فعال است. پس تنها راه تغییر رابط دسکتاپ، پچ `app.asar` است — و پلاگین سرور همان پچ را **خودکار اعمال و بعد از هر آپدیت ترمیم** می‌کند (پایین را ببینید).

## ⚠️ محدودیت مهم (شفاف)

**کادر تایپ پرامپت وقتی هنوز ارسال نکرده‌اید، توسط UI اوپن‌کد رندر می‌شود و هیچ هوک پلاگینی به بافرِ زنده‌ی آن دسترسی ندارد.** برای همین:
- در **اپ دسکتاپ** → این بخش را پچ `app.asar` حل می‌کند (موتور `patch/lib/patch-asar.mjs` به‌همراه بسته‌بند هر سیستم‌عامل). چون هیچ پلاگین/افزونه‌ای به رندرر دسکتاپ دسترسی ندارد، پلاگین سرور خودش این پچ را اعمال و **خودترمیمی** می‌کند — اگر دوست ندارید پلاگین به فایل‌های اپ دست بزند، آپشن `desktop: false` را بگذارید و دستی نصب کنید.
- در **ترمینال/TUI** → سلول‌به‌سلول توسط `@opentui/core` رندر می‌شود و حل نهایی آن با خود اوپن‌کد است؛ اما به‌محض ارسال، پیام شما و پاسخ مدل با لایهٔ ۱ درست می‌شود.
- به‌محض ارسال، همه‌جا (ترمینال، دسکتاپ، وب) درست است.

## 🚀 نصب و فعال‌سازی در اوپن‌کد

پلاگین‌ها را فقط هنگام **استارت اوپن‌کد** بارگذاری می‌کند. بعد از هر تغییر کانفیگ، اوپن‌کد را ببندید و دوباره باز کنید.

### روش ۱ — از npm (بعد از انتشار)

```jsonc
// ~/.config/opencode/opencode.jsonc  (جهانی)
// یا  opencode.jsonc  در ریشهٔ پروژه (محلی)
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": [
    [
      "opencode-rtl-fix",
      { "language": "auto" }
    ]
  ]
}
```

### روش ۲ — از سورس / پوشهٔ محلی

```sh
git clone git@github.com:programmer-1998/RTL_OpenCode.git
cd RTL_OpenCode
npm ci && npm run build
```

سپس آدرس پوشه (یا فایل `dist/server.js`) را در کانفیگ بدهید:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": [
    [
      "/home/<user>/RTL_OpenCode",
      { "language": "auto", "isolateToolOutput": "off" }
    ]
  ]
}
```

> 💡 به‌جای مسیر مطلق می‌توانید `./RTL_OpenCode` (نسبت به پوشهٔ کانفیگ) یا `file:///...` بدهید؛ هر سه فرمت معتبر است.

### روش ۳ — خودکار در پروژه (`auto-detect`)

پلاگین را داخل یکی از پوشه‌های زیرِ خودِ پروژه قرار دهید تا اوپن‌کد بدون کانفیگ پیدایش کند:

```
.opencode/plugin/rtl/package.json
.opencode/plugin/rtl/dist/…
```

### روش ۴ — اوپن‌کد ۲ (v2)

در v2 کلید `plugin` به `plugins` تغییر کرده و پلاگین TUI جدا در `cli.json` تنظیم می‌شود:

```jsonc
// opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    { "package": "opencode-rtl-fix", "options": { "language": "auto" } }
  ]
}
```

```jsonc
// cli.json (برای دستورهای RTL در ترمینال)
{
  "plugins": ["opencode-rtl-fix"]
}
```

این پکیج هر دو API را دارد: ورودی `./v2` (سرور v2 با `ctx.session.hook`) و `./v2/tui` (دستورهای CLI). نگاشت هوک‌ها: `chat.message` → `prompt`، `system.transform` → `context/compaction/generate/title`، `tool.execute.after` → `tool.hook("execute.after")`، `shell.env` → `shell.hook("create.before")`.

> 💡 لایهٔ ۱ (پلاگین سمت سرور که با جاوااسکریپت نوشته شده) روی **لینوکس، مک و ویندوز کاملاً یکسان** کار می‌کند. فقط پچ دسکتاپ (لایهٔ ۲) برای هر سیستم‌عامل فایل جداگانه دارد — پایین را ببینید.

## ⚙️ آپشن‌های پلاگین

| آپشن | پیش‌فرض | توضیح |
| --- | --- | --- |
| `enabled` | `true` | روشن/خاموش کل پلاگین |
| `language` | `"auto"` | `auto` یا `none` یا `fa` / `ar` / `he` / `ur` (اجبار زبان) |
| `systemGuidance` | `true` | افزودن راهنمای RTL به سیستم‌پرامپت (یا متن دلخواه) |
| `isolateUserMessages` | `"auto"` | `off` / `auto` / `always` — ایزوله‌کردن پیام کاربر |
| `isolateAssistantText` | `"auto"` | ایزوله‌کردن پاسخ مدل |
| `isolateToolOutput` | `"off"` | ایزوله‌کردن خروجی ابزارها (اگر کپی/پیست دقیق مهم است خاموش بماند) |
| `inlineControls` | `false` | تزریق نکردن کاراکترهای کنترلِ نامرئی (RLI/LRI/PDI) به متن. در پیش‌فرض، پلاگین کاراکترهای جهت‌دارِ موجود در متن را هم **حذف** می‌کند تا بافر ترمینال و بافت مدل آلوده نشود (پیشگیری از نویز `^`). برای ایزوله‌کردن دستی: `true` |
| `minRtlRatio` | `0.2` | حداقل نسبت کاراکتر RTL برای تشخیص خودکار |
| `minRtlCharacters` | `2` | حداقل تعداد کاراکتر RTL |
| `digitMode` | `"preserve"` | تبدیل ارقام: `preserve` / `latin` / `arabic-indic` / `eastern-arabic` |
| `forceDirection` | `"auto"` | اجبار جهت ایزوله: `auto` / `rtl` / `ltr` |
| `alignRtlParagraphs` | `false` | راست‌چین بصری در ترمینال با padding **(مقدار خام متن را هم عوض می‌کند؛ فقط TUI)** |
| `rtlWrapColumn` | `96` | ستون شکستن سطر برای alignment |
| `rtlAlignColumn` | `96` | ستون راست‌چینی |
| `directionEnv` | `true` | ست کردن `OPENCODE_RTL*` در environment ابزارها |
| `desktop` | `true` | نصب/ترمیم خودکار پچ اپ دسکتاپ (`app.asar` + فونت وزیرمتن) از داخل پلاگین. برای دست‌نزدن به فایل‌های اپ: `false` |
| `debug` | `false` | لاگ از طریق `client.app.log()` |

> **نکتهٔ جهت:** جهت بر اساس «اولین کاراکتر قوی» است؛ جمله‌ای که با فارسی شروع شود RTL و جمله‌ای که با انگلیسی/کد شروع شود LTR در نظر گرفته می‌شود. برای اجبار همه‌چیز به راست‌چین: `"forceDirection": "rtl"`.

## 🔧 عیب‌یابی: نویز `^` هنگام رندر در ترمینال

اگر هنگام رندر متن فارسی در TUI، کاراکترهای اضافه‌ای مثل `^^^^^` می‌بینید، عاملش کاراکترهای **نامرئیِ یونیکد** (isolateهای بیدی مثل U+2066/U+2067/U+2069 یا LRM/RLMِ چسبیده به متنِ کپی‌شده از وب) است که یک رندررِ سلول‌به‌سلولِ ساده‌لوح آن‌ها را درست نمی‌فهمد. راه‌حل این پلاگین:

- از این نسخه به بعد، کاراکترهای کنترلی به‌طور پیش‌فرض **تزریق نمی‌شوند** و کاراکترهای جهت‌دارِ موجود هم از متن جاری **حذف** می‌شوند (`inlineControls: false`).
- اگر دستی `inlineControls: true` گذاشته‌اید و نویز دیدید، آن را خاموش کنید.
- جلسه‌های قدیمی که با نسخه‌های قبلی ساخته شده‌اند ممکن است هنوز این کاراکترها را در متنِ ذخیره‌شده داشته باشند؛ یک جلسهٔ جدید بسازید.

## 🖥️ پچ اپ دسکتاپ (پوشش کامل رابط)

اپ دسکتاپ (Electron) بخش‌هایی از متن را بدون جهت‌دهیِ خودکار رندر می‌کند. پچ یک `<style>` + `<script>` به `out/renderer/index.html` داخل `app.asar` اضافه می‌کند تا **همهٔ سطح‌های متنی** — چت و کامپوزر، تب‌ها، منوها، دیالوگ‌ها، توست‌ها، تنظیمات، درخت/مرورگر فایل، پنل review، ضمیمه‌ها، پرمیشن‌ها و سؤال‌ها — دقیقاً مثل مرورگرهای مدرن عمل کنند (کد، دیف و خروجی شل عمداً LTR می‌مانند). همین پچ فونت **وزیرمتن** را هم به‌صورت base64 جاسازی می‌کند و کل رابط را وزیرمتن می‌کند (بدون نیاز به نصب فونت روی سیستم یا اینترنت).

> 🔁 **مهم:** از نسخهٔ **0.2.0** به بعد، خودِ پلاگین سرور این پچ را اعمال و **خودترمیمی** می‌کند؛ یعنی بعد از هر آپدیت دسکتاپ (که `app.asar` را جایگزین می‌کند) پلاگین دوباره آن را ترمیم می‌کند. نصب دستی اسکریپت‌های زیر فقط برای وقتی است که نمی‌خواهید پلاگین به فایل‌های اپ دست بزند (`desktop: false`)، یا می‌خواهید همین حالا (بدون ری‌استارت) اعمال شود.

پچ از یک **موتور مشترک جاوااسکریپت** استفاده می‌کند (`patch/lib/patch-asar.mjs`) که روی هر سه سیستم‌عامل یکسان کار می‌کند؛ فقط «بسته‌بند» (wrapper) مخصوص هر سیستم‌عامل، مسیر اپ را پیدا و دسترسی لازم (sudo / UAC) را می‌گیرد:

| سیستم‌عامل | فایل نصب | پیش‌نیاز |
| --- | --- | --- |
| 🐧 لینوکس | `patch/linux/desktop-rtl.sh` | node 20+ و sudo |
| 🍎 مک | `patch/macos/desktop-rtl.sh` | node 20+ و sudo |
| 🪟 ویندوز | `patch/windows/desktop-rtl.ps1` | node 20+ |

### نصب روی لینوکس

```sh
sudo bash patch/linux/desktop-rtl.sh
```

### نصب روی مک

```sh
sudo bash patch/macos/desktop-rtl.sh
```

> 💡 اگر بعد از پچ، اپ بالا نیامد (امضای کد شکسته شده)، دوباره امضا کنید:
> `sudo codesign --force --deep --sign - "/Applications/OpenCode.app"`

### نصب روی ویندوز

PowerShell را باز کنید و اجرا کنید:

```powershell
powershell -ExecutionPolicy Bypass -File patch\windows\desktop-rtl.ps1
```

با پنجرهٔ UAC موافقت کنید. (یا مستقیماً روی `patch\windows\desktop-rtl.cmd` دوبار کلیک کنید.)

### این کار چه می‌کند؟

1. یک بک‌آپ از `app.asar` در همان‌جا (`app.asar.bak-rtl`) می‌سازد؛
2. `app.asar` را باز می‌کند، `index.html` را پچ می‌کند (جهت‌دهی + `@font-face` وزیرمتن)، دوباره می‌بندد؛
3. چیدمان `app.asar.unpacked` (ماژول‌های native مانند `node-pty`) را **یکی‌به‌یکی با نسخهٔ قبلی مقایسه و تأیید می‌کند** تا چیزی نشکند؛
4. یک فایل مهر (`app.asar.rtl-stamp`) می‌نویسد که نسخهٔ پچ را نگه می‌دارد؛ پلاگین با همین مهر می‌فهمد پچ تازه است یا نه، و نسخه‌های قدیمیِ پچ را **ارتقا** می‌دهد (بدون پچ دوباره روی پچ).

سپس **اوپن‌کد دسکتاپ را ببندید و دوباره باز کنید**.

### بازگشت (Revert)

```sh
# لینوکس / مک
sudo bash patch/linux/desktop-rtl.sh --unpatch
sudo bash patch/macos/desktop-rtl.sh --unpatch
```

```powershell
# ویندوز
powershell -ExecutionPolicy Bypass -File patch\windows\desktop-rtl.ps1 -Unpatch
```

### 🔁 خودترمیمی بعد از هر آپدیت (پیش‌فرض)

اپ از خودکار-آپدیت استفاده می‌کند و آپدیت فایل پچ‌شده را جایگزین می‌کند. از نسخهٔ **0.2.0** به بعد نیازی به اجرای دستی نیست:

- پلاگین سرور (که همراه دسکتاپ/CLI بالا می‌آید) هنگام لود، وجود و تازگی پچ را چک می‌کند.
- چون `app.asar` در حین اجرا قفل است، پلاگین اول **قابل‌نوشتن‌بودن** فایل را امتحان می‌کند و فقط وقتی اپ بسته است پچ می‌زند؛ در فاصلهٔ اجرا هر ۲ دقیقه دوباره تلاش می‌کند.
- پس: پلاگین را نصب کنید → اپ دسکتاپ را ببندید → دفعهٔ بعد که بازش کنید پچ‌شده است. بعد از هر آپدیت هم همین‌طور خودش ترمیم می‌شود.

> اگر نمی‌خواهید پلاگین به فایل‌های اپ دست بزند: `"desktop": false` بگذارید و از اسکریپت‌های دستی زیر استفاده کنید. هیچ‌کدام از این کارها به `sudo`/UAC نیاز ندارد (مگر اپ در مسیر سیستمی نصب شده باشد).

### نصب دستی (اختیاری)

> مسیر پیش‌فرض: لینوکس `/opt/OpenCode/resources/app.asar`، مک `/Applications/OpenCode.app/Contents/Resources/app.asar`، ویندوز `%LOCALAPPDATA%\Programs\@opencode-aidesktop\resources\app.asar`. اگر جای دیگری نصب است: لینوکس/مک `sudo DESKTOP_ASAR=/path/to/app.asar bash patch/linux (یا macos)/desktop-rtl.sh`، ویندوز `powershell ... -Asar C:\path\to\app.asar`.

## 🧪 تست در اوپن‌کد (گام‌به‌گام)

1. اوپن‌کد را ببندید و دوباره باز کنید (تا پلاگین لود شود).
2. در **دسکتاپ**، این متن را در کادر تایپ بنویسید — باید طبیعی از راست به چپ و با `SINA` وسطش درست دیده شود:

   ```
   سلام من SINA هستم
   ```

3. یک پرامپت ترکیبی با مسیر/کد بفرستید، مثلاً:

   ```
   محتوای فایل src/config.ts را بخوان و لیست بده
   ```

   و بررسی کنید ترتیب `src/config.ts` و جملهٔ فارسی جابه‌جا نشده است.
4. در **ترمینال**، اگر دستور `RTL: Show Status` را دارید اجرا کنید تا وضعیت پلاگین را ببینید:

   ```
   /rtl.status
   ```

5. تست‌های خودکار:

   ```sh
   cd RTL_OpenCode && npm test
   ```
